The Idea Board: a trip's Planen phase

Clickable, in-memory, nothing is saved. Screen copy is German because it is the content being specified; the notes are English like the rest of dev-docs/. Implementation starts when this mockup is approved.

Mode (invariant 5)

What the mockup claims

  • One card type. An idea has a title and optionally a note, a link, one tag from a fixed set and up to four images. A bookmark is an idea with a link — no second entity.
  • Phase frame above M4. Planen | Vorbereiten sits in the page head; M4 is unchanged underneath. No tabs for phases without content.
  • Three states, set by hand: Idee → Shortlist → Verworfen. Votes are a signal and move nothing on their own.
  • Dropping is not deleting. A dropped idea keeps its thread and votes, lives in its own segment and can be brought back. Delete is a separate, confirmed action in the detail sheet.
  • One vote per account, tap again to withdraw. Travelers without an account do not vote.
  • Links are stored, not fetched. No preview in slice 1 — the server makes no outbound request, so all three modes behave the same. Only http(s) is accepted.
  • Tags are a fixed set (Wandern · Baden · Kultur · Essen · Ausflug), one per idea, and they filter the board. A tag says what an idea is.
  • „Geht auch bei Regen" is its own attribute, not a tag: it says when an idea suits, so a museum is Kultur and rain-proof. It filters beside the tags and is what a later weather rule keys on.
  • Cloning a trip does not copy its ideas. A clone repeats a packing effort, not a discussion.
  • Comments reuse the existing thread (comments.idea_id); a new idea or comment notifies the other members.

Still open

  • Which phase does a trip open on? Mocked: the last one visited on this device; first visit → Planen while the packing list is empty.
  • Does a shortlisted idea need a date or day yet, or is that the During-phase day plan?
  • Do the Local-Mode backup and the account export carry ideas, images included? 4 × 500 KB changes a backup's size class.
