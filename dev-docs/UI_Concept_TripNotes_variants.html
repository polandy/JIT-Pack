Der Schlüsselfach-Code, die Nummer vom Pizzakurier: etwas, das ein Mitreisender hinschreibt und alle anderen lesen. Anders als eine Aufgabe hat eine Notiz keinen Zustand für die ganze Reise, sondern einen pro Person: Ich hake sie ab, für Anna bleibt sie neu.

Frage 2: Darf man im Dashboard abhaken? — entschieden: ja

Entschieden am 21.09.: Variante B, das Häkchen sitzt im Dashboard. Das ist eine bewusste Ausnahme von FR-7.4 („das Dashboard meldet, es handelt nicht“), nur für Notizen. Variante A (nur melden) bleibt im Prototyp oben zum Vergleich umschaltbar.

Das Blatt kennt die ganze Geschichte: wer, wann, und, falls angeschaltet, wer’s gesehen hat. Bearbeiten und Löschen für jedes Mitglied wie bei Aufgaben (FR-7.4).

Was der Tipp auf ein Wort macht

Eine Telefonnummer wird ein tel:-Link, ein langer Tipp auf einen Code kopiert ihn. Beides ist reine Darstellung; die Notiz bleibt Text.

Was die Notiz nicht ist

Kein Tresor. Der Code liegt im Klartext bei allen Mitgliedern und im Server-Export. Für ein Schlüsselfach gedacht, nicht für ein Passwort.

Wie es gebaut würde

BausteinEntscheidung
Die NotizEine Zeile in comments mit trip_item_id leer und is_task = 0 — die Form „Kommentar auf der Reise“, die FR-7.1 längst zulässt und die noch kein Bildschirm schreibt. Autor, Zeit, Sync, Export und Löschen sind damit schon da; der Server stempelt den Autor (Invariante 3).
Das Häkchen pro PersonNeue Tabelle note_acks (comment_id, user_id, acked, Feld-HLCs) in der Reise-Partition. user_id stempelt der Server. Wieder entfernen setzt acked zurück, die Zeile bleibt (Feld-LWW löscht nicht).
Warum keine Spalte an der NotizEin Feld acked_by an comments würde Feld-für-Feld zusammengeführt: Annas und Bens Häkchen zur selben Zeit überschreiben sich, einer verliert. Eine Zeile pro (Notiz, Person) kann nicht kollidieren. Das ist der Grund, aus dem template_tasks eine Tabelle wurde, und ein ADR wert.
„Neu für mich“Abgeleitet, nie gespeichert: autor ≠ ich und keine Zeile acked für mich. Eigene Notizen sind nie neu.
DashboardLiest die Notizen aller laufenden Reisen, neueste zuerst, höchstens drei, mit Reise-Chip. Braucht wie die Aufgabenkarte die Reise-Partition der laufenden Reisen.
Drei ModiServer: alles. Single-User: ein Konto, also gibt es keine anderen Autoren, Karte und „neu“ sind still, die Notiz dient als Merkzettel. Local: dasselbe, ohne Nutzer-ID; kein note_acks, nichts, was ein Fremdschlüssel sein müsste.
MitteilungEine neue Notiz löst die bestehende Push-Meldung „an alle Mitglieder“ aus, denn ohne sie liest niemand den Code rechtzeitig. Aus in den Einstellungen wie die übrigen.
Nicht im BackupWie alle Aufgaben und Einkaufseinträge (NFR-4.11).
